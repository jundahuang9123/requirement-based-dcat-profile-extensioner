\paragraph{Application profiles and \acs{DCAT-AP} extensions.}
Profile engineering fixes what a profile contains, functional requirements included
\cite{nilsson2008singapore,coyle2009dcap}, and how it may change its base, by adding constraints only
\cite{w3cdcat3}, not how a requirement becomes an element.
\ac{SEMIC}'s guidance asks use cases to justify new elements and tightened constraints, not every element
\cite{semicreuse2026}.
At best, decisions survive as issues, resolution logs and use cases linked to requirements
\cite{dragan2019maintenance,statdcatap,w3cdcatucr}.
Dataspecer edits profiles of profiles and publishes them in \ac{DSV} and \ac{SHACL}
\cite{stenchlak2022dataspecer,klimek2024dataspecer,klimek2026dsv}. As we read its code, it neither derives them
from requirements nor checks refinement of the base. Its review of base updates for dependent profiles is the
closest pattern we found for machine proposals that a person decides \verify{Dataspecer: code reading only}.
A visual profile editor models \ac{DCAT-AP} extensions as \ac{LinkML} schemas \cite{moxon2026linkml}
\todo{anonymized reference to the profile editor (Q25)}.
Neither the guidance nor Dataspecer fixes how an element records the requirement it serves, the base value it
tightens or the candidates it passed over; we formalize and automate this derivation.

\paragraph{Requirements and reuse in ontology engineering.}
Ontology engineering specifies requirements before it models and looks for existing resources before it builds.
NeOn has scenarios that reuse ontological and non-ontological resources \cite{suarez2012neon}; LOT records
verified requirements in a specification document \cite{suarez2009orsd}, and each implementation sprint searches
existing ontologies with the requirements' terms \cite{poveda2022lot}.
Competency questions mainly fix scope and evaluate the conceptualization \cite{monfardini2023}, and different
elicitation methods draw different questions from one story \cite{alharbi2026cq}.
The companion study judges against the base whether a requirement adds anything \cite{anon2027rq1}; this paper asks
how it adds, by tightening, reusing or minting, a choice bounded by the same base and the vocabularies within
reach.

\paragraph{\acs{LLM}-assisted ontology and shape generation.}
\acp{LLM} generate whole ontologies, or shapes from given terms.
Models elicit competency questions \cite{zhang2024ontochat,lippolis2025bench4ke}, turn them into \ac{OWL} with
Memoryless CQbyCQ and Ontogenia \cite{lippolis2025ontology}, mine schemas from papers with expert feedback
\cite{sadruddin2025schema} and assist domain modelers \cite{prokop2024assistant}; \ac{DCAT} metadata extraction
fills records, not profiles \cite{busch2025dcat}.
NL2SHACL-Bench supplies the relevant ontology terms with each constraint description \cite{zhou2026nl2shacl},
text2shacl writes shapes per property of a railway ontology from its application guide
\cite{martinez2026text2shacl}, and Zhang et al.\ generate ShEx schemas for knowledge graphs \cite{zhang2025schema}.
Closest to our pipeline is RIGOR, whose released implementation enriches a deterministic mapping of a relational
database. Its model writes only deltas, a model judge reviews each, a failed delta is regenerated at most twice, % src: docs/literature-steps.md:24 (G1-S13: at most three attempts per table, MAX_JUDGE_RETRIES = 2)
and every generated term records its source table or column \cite{fathallah2026rigor}.
IDEA2, the companion's closest work, keeps expert votes and a PROV-O history for drafted competency questions
\cite{alharbi2027idea2}.
Like RIGOR, we let the model change a fixed backbone only through checked deltas. We add typed records instead
of model-written syntax, term choice from candidates retrieved for a pinned release, a reason for every
mint, obligations an atom's wording licenses, conformance to the base and a person's sign-off.

\paragraph{Reliability and evaluation of model outputs.}
Majority voting explains most of the gains of multi-agent debate \cite{du2024debate,choi2025debate,smit2024mad}.
\ac{LLM} judges track human ratings \cite{liu2023geval,zheng2023judge} but are swayed by answer order
\cite{zheng2023judge,wang2024fair}, may prefer model-written text, score inconsistently
\cite{liu2023geval,stureborg2024inconsistent} and depend on the prompt \cite{yuan2024batcheval}.
These findings motivate optional independent votes instead of debate, symbolic checks before the model judge and % src: @5ffd56e B/contracts.py:597 (votes: int = 1)
machine decisions a person can overrule.
A cited source need not support the statement that cites it \cite{rashkin2023ais,gao2023alce}, so program code checks
the trace (T1) and a model judges attribution (T2).
Hosted models vary between runs \cite{atil2025nondeterminism,ouyang2025nondeterminism}, benchmarks leak into training
data \cite{sainz2023contamination}, and models lean on familiar words \cite{mai2024adapt} and falter on counterfactual
tasks \cite{wu2024reciting}, hence repeated runs and leakage controls (Sect.~\ref{sec:setup}).
Information retrieval ranks systems reliably despite incomplete and varying judgments
\cite{zobel1998reliable,voorhees2000variations,buckley2004incomplete}; we borrow only the point that an unmatched
change need not be wrong.
Unlike the companion study, we report the share of included changes that match a reference element and adjudicate
the rest (Sect.~\ref{sec:setup}).
