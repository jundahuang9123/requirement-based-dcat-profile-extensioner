\paragraph{Application profiles and \acs{DCAT-AP} extensions.}
Profile engineering fixes what a profile contains, a documentation package with mandatory functional requirements
\cite{nilsson2008singapore,coyle2009dcap}, and how it may change its base, not how a requirement becomes an element.
\ac{SEMIC}'s guidance resolves a use case by reuse, by tightening a base constraint but never loosening one, or by a
term minted in the profile's own namespace, and asks use cases to justify new elements and tightened constraints, not
every element \cite{semicreuse2026}.
At best, practice keeps decisions as issues, resolution logs and links from requirements to use cases
\cite{dragan2019maintenance,statdcatap,w3cdcatucr}.
Dataspecer authors profiles, also of other profiles, and publishes them in \ac{DSV} and \ac{SHACL}
\cite{stenchlak2022dataspecer,klimek2024dataspecer,klimek2026dsv}; in a reading of its code it neither derives a
profile from requirements nor checks that a profile's cardinalities and ranges refine its base, but its review of what
a changed base means for a dependent profile, one decision per item, is the closest pattern we found for a machine
that proposes and a person who decides \verify{Dataspecer: code reading at one commit, nothing run}.
A visual profile editor models \ac{DCAT-AP} extensions in \ac{LinkML} \cite{moxon2026linkml}
\todo{anonymized reference to the profile editor}.
Neither the guidance nor Dataspecer fixes how an element records the requirement it serves, the base value it
tightens or the candidates it passed over, and that derivation is what we formalize and automate.

\paragraph{Requirements and reuse in ontology engineering.}
Ontology engineering specifies requirements before it models and looks for existing resources before it builds:
NeOn includes scenarios that reuse ontological and non-ontological resources \cite{suarez2012neon}, and LOT formalizes
verified requirements in a specification document \cite{suarez2009orsd} before each implementation sprint searches for
existing ontologies with their terms \cite{poveda2022lot}.
Competency questions serve mainly to fix scope and to evaluate the result \cite{monfardini2023}, and different
elicitation methods draw different questions from the same story \cite{alharbi2026cq}.
The companion study judges against the base whether a requirement adds anything \cite{anon2027rq1}; this paper turns
to how it adds, by tightening a base constraint, reusing a term or minting one, which can be judged only against the
same base and the vocabularies within reach.

\paragraph{\acs{LLM}-assisted ontology and shape generation.}
Generators built on \acp{LLM} write whole ontologies, or constraints for terms they are given.
In ontology engineering, models elicit and generate competency questions \cite{zhang2024ontochat,lippolis2025bench4ke},
turn them into \ac{OWL} one question per call or along a nine-step procedure, as the released prompts of Memoryless
CQbyCQ and Ontogenia do \cite{lippolis2025ontology}, % src: docs/literature-steps.md:14-15 (G1-S03, G1-S04)
mine schemas from papers with expert feedback \cite{sadruddin2025schema} and assist domain modelers
\cite{prokop2024assistant}; extracting \ac{DCAT} metadata fills catalog records, not profiles \cite{busch2025dcat}.
NL2SHACL-Bench pairs constraint descriptions and the relevant ontology terms with reference shapes
\cite{zhou2026nl2shacl}, text2shacl writes shapes for each property of a railway ontology from its application guide
\cite{martinez2026text2shacl}, and Zhang et al.\ generate ShEx schemas for knowledge graphs \cite{zhang2025schema}.
Closest to our pipeline is RIGOR, whose released implementation enriches a deterministic mapping of a relational
database: the model writes only deltas from retrieved context, a model judge approves, corrects or rejects each, a
rejected or invalid delta is regenerated at most twice with the issues fed back, % src: docs/literature-steps.md:24 (G1-S13: at most three attempts per table, MAX_JUDGE_RETRIES = 2)
and every generated class and property records its source table or column \cite{fathallah2026rigor}.
IDEA2, the companion study's closest work, keeps expert votes and a PROV-O history for drafted competency questions
\cite{alharbi2027idea2}.
Like RIGOR we let the model change a fixed backbone only through checked deltas, and we add typed change records in
place of model-written syntax, term choice among retrieved candidates of a pinned release, mint decisions with their
reasons, obligations licensed by a requirement's wording, conformance to the base and a person's sign-off.

\paragraph{Reliability and evaluation of model outputs.}
Majority voting over independent answers explains most of what multi-agent debate gains
\cite{choi2025debate,smit2024mad,du2024debate}.
\ac{LLM} judges correlate with human ratings \cite{liu2023geval,zheng2023judge} but are swayed by the order of the
answers \cite{zheng2023judge,wang2024fair}, may prefer model-written text and score inconsistently
\cite{liu2023geval,stureborg2024inconsistent} and depend on the prompt's design \cite{yuan2024batcheval}, and the
slides released with OE-Assist report that wrong model suggestions lowered reviewers' accuracy
\cite{lippolis2025oeassist}.
A cited source need not support what cites it \cite{rashkin2023ais,gao2023alce}, which is why program code checks the
trace (\term{T1}) and a model judges attribution (\term{T2}).
Hosted models vary between runs even under deterministic settings
\cite{atil2025nondeterminism,ouyang2025nondeterminism}, benchmarks leak into training data
\cite{sainz2023contamination}, models rely on the words of familiar concepts more than on their relations
\cite{mai2024adapt}, and performance falls on counterfactual variants of familiar tasks \cite{wu2024reciting}.
These findings shape the design: one vote by default, % src: @5ffd56e B/contracts.py:597 (votes: int = 1)
independent votes as an option, symbolic checks before the model judge, machine decisions that a person can
overrule, and repeated runs on fresh stores with leakage controls (Sect.~\ref{sec:setup}).
Information retrieval ranks systems reliably with incomplete pools and varying assessors
\cite{zobel1998reliable,voorhees2000variations} and with measures that use judged items only
\cite{buckley2004incomplete}; we take from this only that a change matching no reference element is not necessarily
wrong.
Unlike the companion study, we report the share of included changes that match a reference element, a precision
against one published modeling, and adjudicate the unmatched changes instead of counting them as errors
(Sect.~\ref{sec:benchmark}).
