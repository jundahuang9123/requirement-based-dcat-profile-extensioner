\section{Changes for a DCAT-AP Extension}\label{sec:problem}

We distinguish changes by what they do to the base (Table~\ref{tab:kinds}): a change \emph{refines}, \emph{reuses} % src: @5ffd56e B/contracts.py:37-46 (six ChangeKind values)
or \emph{mints} a property, reuses or mints a class, or adds a \emph{usage note}. Each atom first receives a % src: @5ffd56e B/contracts.py:699-706 (usage notes are not scored; Sect. 5 says so)
\emph{disposition}: covered by the base, needs a change, out of scope (not catalog content) or unclear. This % src: @5ffd56e B/contracts.py:65-70 (four AtomDisposition values); B/engine/prompts.py:62-64
classification is ours, ordered as \ac{SEMIC}'s guidance resolves a requirement~\cite{semicreuse2026}, not a % src: LIT G3-S01 (four-rung ladder; implemented, Ours): docs/literature-steps.md:74
general taxonomy of ontology changes.

The task, in one sentence: given requirement atoms and a pinned \acs{DCAT-AP} release as the base, decide which
atoms the base already meets, and produce changes that reuse before they mint (E1), trace to atoms that license
their obligation (E2), carry decisions a person can inspect and overrule (E3), and keep the extension conformant to
the base (E4). % src: @5ffd56e docs/design.md:5-10 (goals); outline Sect. 2 (E1-E4 = pillars 1-4)

An \emph{atom} has an identifier, a modality (must, should, may or unspecified), an optional source reference, % src: @5ffd56e B/contracts.py:32 (Modality), 133-151 (Atom)
and a subject such as \emph{dataset} and a statement, both in plain words without \acp{IRI} or prefixed names. % src: @5ffd56e B/engine/intake.py:39-51 (an IRI or a prefixed name in the statement is an error), 22, 52-55 (subject: plain lower-case words, else a warning)
The \emph{base} pairs a \acs{DCAT-AP} release with the \acs{DCAT} version the release states it builds on, % src: @5ffd56e B/contracts.py:238-250 (DcatBasis); B/data/base-profiles/dcat-ap-1.1/profile.yaml:33; B/data/base-profiles/dcat-ap-3.0.1/profile.yaml:43
DCAT~2014 for 1.1 and DCAT~3 for 3.0.1~\cite{dcatap11,semicdcatap301}. \verify{release quotes: DCAT version} % src: DCS §1.2 (the quotes are recorded in profile.yaml, not re-checked against the releases)
Its \emph{base elements}, one per class and property, carry \emph{facets} (obligation, cardinality, range, node % src: @5ffd56e B/contracts.py:194-217 (Facets, BaseElement); B/knowledge/shacl_reader.py:79-106
kind, value list, pattern) merged from the official \ac{SHACL} shapes and, as these state only mandatory ones, % src: @5ffd56e B/knowledge/base_profile.py:233-240; @5ffd56e docs/conformance.md:33-36; KCU §1.3
the specification's obligation levels. A pair the specification lists without a shape has only an obligation. % src: @5ffd56e B/knowledge/base_profile.py:76-81, 245-266; DCS §3
From 2.1.0 on, a property \acs{DCAT} lists for a class but the release omits is optional there, a reuse % src: DCS §1.2 (2.1.0, 2.1.1, 3.0.0, 3.0.1: unlisted_dcat_properties optional); @5ffd56e B/contracts.py:246-248
candidate, not a base element. \verify{release text: optional-field rule} % src: DCS §7 item 15; @5ffd56e B/engine/retrieve.py:134-156; B/engine/verify.py:319-320 (constraining it is an addition)
An index of 926 to 933 terms per base holds the base's terms, those of 12 other vocabularies and all 60 % src: paper/inputs/tool-facts-main-5ffd56e.txt:2, 6-14 (926 to 933; 12 vocabularies); DCS §1.1 (60 DCAT terms), §2.3; @5ffd56e B/knowledge/__init__.py:80-129
\acs{DCAT} terms. For the base's \acs{DCAT}, each \acs{DCAT} term is current, deprecated, later, removed or % src: @5ffd56e B/knowledge/dcat_state.py:127-146; B/knowledge/__init__.py:63-69 (adopted); DCS §2.2
adopted (later, but used by the base).

A \emph{change} is one decision on one element: a class and, for a property change, a property with facets. % src: @5ffd56e B/contracts.py:385-420 (ProfileChange)
Its \emph{justification contract} holds \emph{coverage links}, each naming an atom with a reason, a quote of its % src: @5ffd56e B/contracts.py:334-340 (CoverageLink)
statement and full or partial coverage, and the records of its kind (Table~\ref{tab:kinds}). Program code, % src: @5ffd56e B/contracts.py:343-367 (FacetJustification, MintJustification; rejected candidates only when the model names them: ADD §H)
not the model, sets the kind from the base and the namespace, mints every identifier and writes each % src: @5ffd56e B/engine/propose.py:191-204 (kind from the facts), 240-266 (reasons default to the rationale), 287; B/knowledge/__init__.py:38-45 (NEW:localName)
\emph{facet justification}, the base value beside the new one. An atom \emph{licenses} an obligation by its % src: @5ffd56e B/contracts.py:343-356 (FacetJustification; status filled by V3: B/engine/verify.py:310-317)
modality: must licenses mandatory, should recommended, may optional and, by our choice, unspecified recommended; % src: @5ffd56e B/contracts.py:712-715 (MODALITY_OBLIGATION)
a change is licensed by its strongest atom. Included changes compile to the \emph{ProfileDelta}, elements keyed % src: @5ffd56e B/engine/verify.py:463-471 (maximum over the covered atoms)
by class and property with kind, facets and status against the base. The criteria restate the pillars of % src: @5ffd56e B/contracts.py:457-483; B/compile/model.py:52-78 (added, tightened or loosened; never unchanged: ISS E7.13); B/contracts.py:9-13 (the same contract as the reference deltas, PE:1-28; Sect. 5 says so)

\begin{description}
\item[E1 Reuse first and minimal.] An atom the base already meets gets no change (B1 checks the claim). Otherwise % src: @5ffd56e B/engine/prompts.py:35-38; B/engine/propose.py:108-112; B/engine/verify.py:513-533 (B1)
  a change tightens what the base states before using another term, prefers properties the base's \acs{DCAT} % src: @5ffd56e B/engine/prompts.py:35-46 (procedure steps 4-6)
  lists for the class and reuses before minting. Minimality is local, not global: each change covers % src: @5ffd56e B/engine/verify.py:445 (T1 no atom), 351-356 (V3 no_effect), 493-510 (V5 duplicate_element)
  an atom, each refinement tightens a facet, and each class and property has one element.
\item[E2 Traced and licensed.] Every change covers at least one existing atom, each link with a reason and a quote % src: @5ffd56e B/engine/verify.py:442-454
  found in the atom's statement up to case and whitespace. Each facet it sets has a reason, and a property % src: @5ffd56e B/engine/verify.py:86-87 (whitespace collapsed, lowercased), 455-462, 472-474
  change's obligation stays within what its atoms license. T1 checks this mechanically; whether the atoms % src: @5ffd56e B/engine/verify.py:463-471 (not checked for class changes and usage notes); the mint justification is V4's: :365-399
  support the change, other facets included, is a separate, fallible judgment (T2). % src: @5ffd56e B/engine/pipeline.py:221-244
\item[E3 Decided, inspectable and overrulable.] Every change records its decision, who made it (a rule, the model % src: @5ffd56e B/contracts.py:91, 298-307, 378-382 (AuthorType, Provenance, Decision)
  or a person) and its inputs, model calls included. A person can overrule any decision, no machine stage % src: @5ffd56e B/contracts.py:549-571 (LLMCallRecord with full prompts); B/engine/pipeline.py:493-555
  overwrites a person's, and only a person's sign-off releases the extension. % src: @5ffd56e B/engine/pipeline.py:58-60, 246-248, 283-285, 618-640; ENG §4
\item[E4 Conformant to the base.] Every constraint is added or tightened, never loosened or contradicted, in a % src: @5ffd56e B/conformance/refinement.py:83-230 (unchanged since 2b92d77: ISS header); B/engine/verify.py:291-357
  legal-refinement order: a minimum may rise, a maximum fall, a range narrow to a known subclass, value lists and
  node kinds shrink and obligations rise, but a datatype never changes. Minted terms are new, reused terms % src: @5ffd56e B/engine/verify.py:95-158 (V1); B/conformance/check.py:149-168 (C3, C4)
  exist, \acs{DCAT} terms belong to the base's \acs{DCAT} or, by default, are later ones a person accepts, and base % src: @5ffd56e B/engine/verify.py:219-283 (D1-D3); B/contracts.py:604-606; B/engine/pipeline.py:260-263; B/conformance/check.py:64-99 (C8)
  and extension are jointly satisfiable. Validated with the official shapes, the extension's own shapes cannot % src: @5ffd56e B/compile/shacl.py:27-32 (validate with the base shapes); B/compile/model.py:43-44 (shape IRIs in the extension's namespace)
  relax them; the conformance rules test the rest (Sect.~\ref{sec:compile}). % src: KCU §4.4 (data valid under base and extension is valid under the base; the base-only branch of C7 cannot fire); @5ffd56e docs/conformance.md:41-65 (C1-C8)
\end{description}

Several modelings can meet one atom, and a published profile may rest on choices no requirement states, left % src: RQ1 L223-227 (pattern)
unwritten as tacit knowledge~\cite{gervasi2013tacit}. A reference element no atom asks for therefore stays
outside the denominator: beyond the atoms' reach, not a miss (Sect.~\ref{sec:benchmark}).

A change is \emph{proposed}, then \emph{auto-accepted} by the decision policy of Sect.~\ref{sec:check}, a state % src: @5ffd56e B/contracts.py:81-89 (DecisionStatus); B/engine/pipeline.py:246-267
the companion workflow lacks~\cite{anon2027rq1}, or left \emph{waiting for review}. A person \emph{accepts} or % src: RQ1 L228-232 (no automatic acceptance there)
\emph{rejects} it by a recorded decision, the model may \emph{withdraw} it in repair (stored as rejected), and a % src: @5ffd56e B/engine/pipeline.py:493-536 (decided_by human:<name>); B/contracts.py:86 (rejected: a person, or a withdrawal)
repair, an edit, a merge or a new proposal \emph{supersedes} it. The \emph{included} changes, auto-accepted or % src: @5ffd56e B/engine/pipeline.py:175-178, 311-331, 512-531; B/engine/consolidate.py:25-95
accepted, form the extension. These are workflow states, not guarantees of correctness. % src: @5ffd56e B/contracts.py:89 (INCLUDED_STATUSES); B/compile/model.py:47-49
